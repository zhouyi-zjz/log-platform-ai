log-platform-ai · 高并发压力点定位
本平台两类典型高并发：写放大（采集洪峰，瓶颈=ES 写入吞吐 / 消费 lag）与 读放大（突发查询，瓶颈=ES 查询线程池 / 深分页 / 聚合）。绿色框=稳定层，红色=压力热点，蓝字=关键解决方案。
① 写入链路（削峰填谷 · 不可丢）
业务应用
OTel/SkyWalking 采集 Trace + 应用日志 JSON
→
Fluent Bit
本地磁盘缓冲，扛住采集端瞬时高峰
→
ingest 入口（压力点①）
校验 Token / ≤1MB，异步投 Kafka 即返回 202
解：Token 鉴权·大小校验·入口限流
→
Kafka logs.raw
6 分区 / RF2 · key=项目|服务|环境
解：削峰填谷·分区并行·保序
→
批量消费端（压力点②）
批量拉取→归一化→ES Bulk
解：batch 1000/1s·重试3次·DLT·幂等 create
→
ES Data Stream
ILM 7 天 · 冷热分层
解：分片均衡·扩容加 data 节点
背压闭环：ES bulk 失败 → 整批重试（FixedBackOff 1000ms×2）→ 仍失败进 logs.raw.DLT 死信；监控 consumer lag 与 ES bulk 拒绝率 触发扩容阈值。
② 查询链路（读放大 · 快而稳）
前端 Vue /monitor
大屏·检索·AI 分析（SSE）
解：分页·防抖·预聚合
→
限流器（压力点③）
LogQueryLimiter
解：120/min 滑动窗口·Semaphore 20 全局并发→ 演进为 Redis 分布式
→
查询服务（压力点④）
拼 DSL·权限时间窗口
解：search_after 深分页·timeout 3s·track_total_hits=10000·groupBy≤3
→
ES _search
查询线程池共享
解：读写分离·查询缓存·线程池隔离·熔断降级
查询隔离：普通用户仅当天窗口 / 管理员最多 168h（LogQueryWindowService 强制，非前端传参）；深翻页用 search_after 游标，禁止前端自定义游标。
